# Working on this repo

You are probably an AI assistant reading this because a person asked you to
change, deploy or extend the Ace Games website. This file is the contract.
Read it fully before touching anything. It is short on purpose.

Companion files: `AI-HANDOVER.md` (how to do every common task, step by step),
`docs/RECIPES.md` (copy-paste task recipes), `DEPLOY.md` (going live),
`PLAN.md` (why the design is the way it is), `TODO.md` (figures the owner
still has to supply).

## What this is

The acegames.io website. Ace Games is a B2B iGaming studio: it builds slot,
instant and table games and licenses them to casino operators. It does not
take bets and has no consumer product. The audience for every page is an
operator's game acquisition or compliance team. Everything on the site is
built by Ace Games in-house, including the game engines behind the demos.

The site is **static HTML generated by Astro 5**. Directus and PostgreSQL are
editorial/build-time services, never browser runtime dependencies. In the
transition `CONTENT_SOURCE=local` reads the legacy Markdown backup;
`CONTENT_SOURCE=cms` synchronizes one immutable release snapshot before the
build. The result remains a folder of files any CDN can serve.

## Commands

```bash
npm install          # once, Node 20 or newer (see .nvmrc)
npm run dev          # http://localhost:4321, hot reload (add -- --port 4400 if 4321 is busy)
npm run build        # writes dist/
npm run verify       # the parity gates against dist/
npm run ship         # build + verify; every gate must pass before any deploy
npm run new-game     # scaffolds a game record, see AI-HANDOVER.md
npm run cms:bootstrap # installs Directus schema, seeds and access policies
npm run test:cms-model # schema, migration, release and localization tests
npm run cms:parity    # compares all migrated games with the local backup
npx astro check      # TypeScript diagnostics, must report 0 errors
```

`npm run ship` is the definition of done. If a gate fails, fix the cause; never
weaken the gate. The gates are in `scripts/verify.mjs`, and each one exists
because the previous site failed it. The single sanctioned edit to that file
is removing a retired slug from the `OLD` list, in the same commit as its 301
in `public/_redirects` (see the retire recipe).

The showcase components:

- `Wall.astro`: the hero, three drifting rows of the catalogue's own key art
  in shallow perspective; GSAP ScrollTrigger (lazy-loaded) flattens it on
  scroll. Static tilted wall without JS or under reduced motion.
- `GameTile.astro`: catalogue tile with art, type badge, RTP and a four-bar
  volatility meter; the game name remains available to assistive technology
  but is not duplicated visually over artwork that already contains it.
- `Excellence.astro`, `ExperienceCard.astro` and `ScalableCardFrame.astro`:
  the three-card iGaming excellence section. Desktop and phone use vertical
  cards; tablet uses a horizontal art-and-copy layout. Pointer devices get
  configurable tilt, depth and glare.
- `OrbitBorder.astro`: the independent animated trail around the main
  navigation border. It is not part of the experience-card effect.
- `MathsExplorer.astro`: the "every game by the numbers" board, four
  volatility lanes with each game's art placed by RTP, hover card, filter
  that dims instead of hiding.
- `GameHeader.astro` and `SpecStrip.astro`: the game page header (layered
  art, parallax key art) and the six-cell spec strip under it.
- `Craft.astro`: the single inverted cream block (maths, art, engine).
- `PartnerWall.astro`: operator logos; renders nothing while `partners` in
  `site.ts` is empty.

## Invariants. Do not break these.

1. **URLs do not change.** Games live at `/portfolio/<slug>` because those are
   the URLs Google already knows. A slug may be renamed or retired only with a
   301 in `public/_redirects` in the same commit; that is also the one case
   where the `OLD` list in `scripts/verify.mjs` is edited. Tell the owner that
   adapter demo records on the game server hold the old lobby path.
2. **Content is visible without JavaScript.** The reveal animation adds the
   hidden start state from script; the CSS ships visible. Never write an
   element whose only route to being visible is a script.
3. **Labels live in templates, values live in content.** A game record holds
   `rtp: 0.945`; the template prints `94.5%`. Do not add label fields to a
   record, do not format numbers inside content files.
4. **No `demo` block means no iframe.** The demo section renders only when the
   record has one. Never emit an empty `<iframe src="">`.
5. **Demo URLs are built, never stored.** `demoUrl()` in `src/lib/format.ts`
   assembles them from `{ mode, gameId }` or `{ mode, build, version, apiHost }`.
   Adapter demos get a lobby URL derived from the page's own slug; direct
   builds carry none.
6. **One `<h1>` per page, and it names the page.**
7. **Every raster image goes through the Astro asset pipeline.** Use `<Image>`
   with an explicit `sizes`, or `getImage()` when an optimized image must be
   consumed by CSS, as in the scalable nine-slice card frame. Never hand-write
   `<img src="/src/assets/...">`. The one exception is operator logos: SVGs
   in `public/partners/`, rendered by `PartnerWall.astro` with fixed dimensions.
8. **Nothing from the old site comes back.** `verify.mjs` fails on the strings
   `webflow`, `website-files`, `Brandfluencer`, `tncflow`, `marketplace-checkout`,
   `_CHEB`, `utility/style-guide`, `placeholder.60f9b184`, `Grow With Authentic`.
   The legal pages are exempt for `webflow` and `website-files` only, because
   they name the former host as a processor.
9. **Filters reorder and dim; they never hide.** A buyer who taps "Slots" gets
   slots first and still sees the rest. This holds for the catalogue and the
   maths board.
10. **No placeholders, no invented facts.** A leftover `TODO` from the
    scaffolder fails the gates, as does an em-dash in copy. `TODO.md` lists
    every figure the owner has not supplied (certificates, jurisdictions, operator counts, logos). Each one
    renders as a dashed orange underline on the page. Leave the gap visible
    rather than fill it with a plausible number, a made-up licence line, or
    a competitor's logo.

## Design rules

The brand: orange `#FF5600`, near-black `#111110`, cream `#FFFFF5` for exactly
one block per page, peach `#F6CB95` for emphasis inside display type. Tanker
for display, Inter Variable for body, JetBrains Mono for data. Six pastel
tints (`--tint-*`) for icon tiles and type badges, nothing else.

- Use tokens from `src/styles/tokens.css` for colours, radii and durations.
  Raw `rgb()` values are acceptable only inside gradient scrims and overlays.
- Current orange buttons use white text and white icons through
  `--on-brand-button`, by the owner's explicit visual decision. Keep labels
  large and bold enough for this treatment; do not use it for small body text.
- One accent. The wall is the one bold move on the home page; keep the rest
  quiet. Do not add gradients, glows, particles, or a second marquee.
- Motion only on `transform` and `opacity`, only with a reason (hierarchy,
  storytelling, feedback), always gated behind `prefers-reduced-motion`.
- `/effects-lab` tunes experience-card motion and navigation Border Trail as
  two independent effects with separate Apply, Copy and Reset actions. Do not
  merge them or expose this technical route in public navigation.
- Buttons are pills. Cards use `--radius-l`. Do not mix.
- No em-dashes anywhere in copy. Use a comma, a full stop, or a colon.
- No emoji in markup or copy. Icons come from `astro-icon` (`ph:` Phosphor).
- Plain functional labels. No "Quietly trusted by", no section numbers, no
  scroll cues, no version stamps.

## When a person asks you to change something

1. Read the relevant recipe in `docs/RECIPES.md` and the matching section of
   `AI-HANDOVER.md` first; most requests are already covered step by step.
2. In CMS mode, content goes to Directus working data and is published through
   a release. In local transition mode use `src/content/` or `src/data/site.ts`;
   never maintain both as parallel editable sources.
3. Run `npx astro check` (0 errors) and `npm run ship` (every gate passes).
4. Open the page in a browser (`npm run dev`) and look at it at 375 px and
   1440 px before saying it is done.
5. Tell the person what changed, what you verified, and anything you could
   not verify.

If a request would break an invariant above, say so and offer the nearest
change that does not.
