# Ace CMS: быстрый старт для владельца сайта

Ace CMS — это закрытая панель управления контентом Ace Games. Здесь можно менять игры, тексты, изображения, FAQ, порядок карточек и переводы без редактирования кода.

## 1. Как запустить CMS в первый раз

Нужны установленный Node.js и запущенный Docker Desktop. В папке проекта выполните:

```powershell
npm install
npm run cms:setup
```

Команда сама создаёт локальные пароли, запускает PostgreSQL и Directus, создаёт структуру CMS, загружает 24 текущие игры и их изображения, запускает сайт и выполняет smoke test. Пароли не попадают в Git.

Успешный запуск заканчивается сообщением `Ace CMS ready`.

## 2. Куда зайти

- CMS: <http://localhost:8055>
- сайт: <http://localhost:4321>

Оба адреса должны быть открыты одновременно: в CMS вы меняете контент, на сайте проверяете результат.
Если порт 4321 уже занят другим локальным сайтом, setup автоматически выберет свободный порт 4322–4330 и напечатает фактический адрес.

## 3. Как войти

Локальный логин создаётся автоматически. Посмотреть его и пароль можно командой:

```powershell
npm run cms:credentials
```

По умолчанию email — `admin@acegames.local`. Пароль хранится только в локальном файле `cms/.env`.

## 4. Где увидеть игры

После входа откройте **Content → Games**. В таблице сразу видны настоящие игры Ace Games: Ace City, Pirates Rush, Gold of Ra и остальные.

Основные колонки:

- **Order** — порядок карточек;
- **Game** — внутреннее имя;
- **Status** — Live или Coming Soon;
- **Type**, **RTP**, **Volatility**, **Demo**;
- **Card**, **Hero**, **Translations**, **Updated**.

В верхней части таблицы доступны поиск, фильтры, сортировка и выбор нескольких строк.

## 5. Как изменить Pirates Rush

1. В **Games** найдите и откройте **Pirates Rush**.
2. Вверху записи откройте список **Main** и выберите **Create Version**.
3. Назовите версию понятно, например `Pirates description update`.
4. Откройте группу **Localization → Translations → English**.
5. Измените `Short Description`, `Overview` или нужное поле.
6. Нажмите **Save**.

Сохранённая версия — безопасный черновик. Пока она не опубликована, сайт читает прежний Main.

## 6. Как нажать Publish

1. Оставаясь в сохранённой версии, снова откройте список версий сверху.
2. Выберите **Promote Version**.
3. Проверьте список изменений.
4. Подтвердите кнопкой **Save**.

В стандартном интерфейсе Directus действие Publish называется **Promote Version**: оно переносит выбранный черновик в Main. В live-режиме именно Main показывается сайтом. Никаких release snapshot, checksum или webhook для локального теста не требуется.

## 7. Где увидеть результат

Откройте или обновите:

- каталог: <http://localhost:4321/games>
- Pirates Rush: <http://localhost:4321/portfolio/pirates-rush>

Серверный cache живёт 5 секунд, поэтому изменение обычно видно сразу или после повторного обновления через несколько секунд. Контент приходит в готовом HTML; браузер не обращается к Directus за текстами.

## 8. Как изменить перевод

1. Откройте **Pirates Rush → Localization → Translations**.
2. Добавьте или выберите **Italian**.
3. Заполните `Display Name`, `Short Description`, `Overview`, SEO и alt-тексты.
4. Сначала используйте статус **Draft**, после проверки — **Approved**.
5. Сохраните и опубликуйте версию через **Promote Version**.
6. Проверьте <http://localhost:4321/it/portfolio/pirates-rush>.

Активные тестовые языки: EN, IT, DE и ES. Если одобренного значения на выбранном языке нет или конкретное поле пустое, сайт подставляет English. Языки добавляются и выключаются в **Locales** без изменения schema.

## 9. Как загрузить картинку

1. Откройте игру и группу **Media**.
2. В **Card Image** или **Hero Image** нажмите выбор файла.
3. Выберите **Upload File**, дождитесь preview и сохраните запись.
4. Для галереи откройте **Gallery → Add Item → File**.
5. Для каждого изображения заполните English alt в переводе.
6. Опубликуйте версию и обновите страницу игры.

Файлы игр хранятся в папке **Games** в Media Library. Для production можно подключить S3-compatible storage без изменения контентной модели.

## 10. Как создать игру

1. Откройте **Games → Create Item**.
2. Заполните **General**: Internal Name, уникальный slug, Status, Order и Type.
3. Заполните **Game Data**: RTP, Volatility и остальные характеристики.
4. Добавьте Card и Hero в **Media**.
5. В **Demo** либо полностью настройте игру, либо оставьте `Demo Enabled` выключенным.
6. В **Localization → Translations** добавьте English, заполните все обязательные поля и поставьте **Approved**.
7. Сохраните запись.

Для `Coming Soon` карточка остаётся в каталоге, но Play и demo не показываются; такая игра не попадает в Maths Explorer. Slug становится адресом `/portfolio/your-slug`.

## 11. Как остановить CMS

```powershell
npm run cms:stop
```

Команда выключает сайт и контейнеры, но не удаляет PostgreSQL и загруженные файлы.

## 12. Как снова запустить CMS

```powershell
npm run cms:start
```

Для обычной совместной работы сайта и CMS можно использовать и `npm run cms:dev`. Проверить состояние:

```powershell
npm run cms:status
npm run cms:smoke
```

Полная очистка локальной базы намеренно требует явного подтверждения:

```powershell
npm run cms:reset -- --confirm-destroy-local-cms
```

Эта команда безвозвратно удаляет только локальные Docker volumes CMS. Обычный `cms:stop` данные не удаляет.

## Что меняется через CMS, а что через code deploy

Через **CMS Publish** меняются тексты, игры, изображения, переводы, FAQ, порядок, status и характеристики.

Через **code deploy** меняются layout, новые компоненты, анимации, CSS и бизнес-логика. CMS не является произвольным page builder.

## Проверка полного редакторского сценария

Разработчик может запустить безопасный интеграционный тест:

```powershell
npm run cms:workflow-test
```

Он временно создаёт CMS Test Game, проверяет Coming Soon, перевод, fallback, порядок, upload, замену Hero и Publish, после чего удаляет тестовую игру и возвращает Pirates Rush в исходное состояние.

## Реальные скриншоты

Для руководства предусмотрены только скриншоты фактически запущенной локальной CMS: Login, Games table, Pirates Rush editor, Translations и Media Library. Макеты вместо Directus UI не используются. Файлы сохраняются в `docs/assets/cms/` после первого успешного запуска окружения.
