# acegames.io, showcase build

The design-led version. Same content, schema, assets and parity gates as the
base build; a new visual layer meant to impress an operator's Head of Games.
Start with `PLAN.md` for the reasoning, `AGENTS.md` for the rules.

The Ace Games site, rebuilt off Webflow. Static HTML is generated by [Astro](https://astro.build).
Directus and PostgreSQL provide a private build-time CMS; no visitor browser
queries the CMS and no runtime JavaScript framework is required.

## Current stable snapshot

The 6 September 2026 checkpoint contains 24 game records and builds 33 static
pages in the default English-only local mode. It adds a Directus/PostgreSQL CMS,
release snapshots, Google Sheets bulk editing and locale-ready routes while
keeping the public output static. In addition to the public home, catalogue,
game, event and legal routes, it includes the private technical route
`/effects-lab`. The lab is excluded
from navigation and the sitemap, carries `noindex`, and lets an editor tune two
independent browser-side effects:

- experience-card tilt, scale, depth and glare;
- the animated Border Trail around the main navigation.

Each tool has its own live preview, Apply to site, Copy settings and Reset
actions. Applied values are stored separately in the current browser. The
public site still builds to static HTML and needs no runtime framework.

## Running it

```bash
npm install     # once
npm run dev     # http://localhost:4321
```

Other commands:

| command | what it does |
| --- | --- |
| `npm run build` | writes the finished site to `dist/` |
| `npm run verify` | runs the parity gates against `dist/` |
| `npm run ship` | build, then verify, in one go |
| `npm run preview` | serves `dist/` exactly as a host would |
| `npm run new-game -- --slug x --name "X" --type slot` | scaffolds a game record |
| `npm run test:cms-model` | validates CMS schema, migration, localization and releases |
| `npm run cms:parity` | compares a migration package with all local game records |

`npm run ship` is the one to use before deploying. It fails if any gate fails.

## Adding a game after CMS cutover

Use **Games → Create Item** in Directus, upload Card/Hero, fill the English
translation and publish the selected game. The complete non-developer workflow
is in `docs/CMS.md`; every field is documented in `docs/CMS-GAMES.md`.

During migration only, `CONTENT_SOURCE=local` keeps the existing Markdown as a
read-only fallback. Do not edit Markdown and CMS as two sources of truth.

### The schema is the safety net

`src/content.config.ts` types every field, and a record that breaks the rules
stops the build with a line number instead of publishing quietly. Concretely:

- `rtp` is a number between 0.80 and 0.995, or the literal `configurable`. It is
  written `0.945` and rendered `94.5%` from one place, so it can never appear
  as a raw decimal again.
- `volatility` comes from a fixed list, so a volatility value can no longer end
  up in the max win column.
- `demo` is structured data, not a URL. The template builds the address and
  derives `lobbyUrl` from the page's own slug, so a demo cannot send a player
  back to a different game's page.
- No `demo` block means no embed is rendered at all. An empty `<iframe src="">`
  is unrepresentable.
- The labels in the spec table live in the template. An editor edits values only,
  so label and value cannot be swapped.

## Layout

```

  assets/           images, optimised at build time
  components/       Header, Footer, contact UI, StatTile, DemoEmbed, and showcase/
  content/games/    24 markdown files, one per title
  content/legal/    privacy policy and terms
  data/site.ts      nav, CTA, stats, FAQ, integration table: content, not markup
  data/*-settings.ts  defaults and storage contracts for the Effects Lab
  lib/format.ts     RTP, max win, volatility and demo URL formatting
  lib/*-motion.ts   card motion and navigation Border Trail behavior
  layouts/Base.astro  head, SEO, canonical, JSON-LD, skip link, scroll reveal
  pages/            index, games, portfolio/[slug], event, effects-lab, legal, utility routes
  styles/           tokens.css, base.css, fonts.css
functions/
  api/contact.ts    the contact form handler, a Cloudflare Pages Function

  _headers          CSP and cache headers for Cloudflare Pages

```

## What still needs your input

`TODO.md` lists it, and every gap shows on the page with a dashed orange
underline rather than being silently filled in. Nothing there blocks the build.

The three that matter most: the testing laboratory and certificate numbers, the
jurisdictions you can supply, and the integration route. Those are the questions
an operator's game acquisition team asks first, and the old site answered none of
them.

## Deploying

Built for Cloudflare Pages: build command `npm run build`, output directory
`dist`. Bandwidth is not metered there, so an art-heavy site does not turn
into a recurring bill.

Full steps in [`DEPLOY.md`](./DEPLOY.md). The short version:

- Build command `npm run build`, output directory `dist`, `NODE_VERSION` = `20`.
- The contact form works once three environment variables are set. See
  [`.env.example`](./.env.example).
- **Export the existing form submissions from Webflow before cancelling.** Every
  lead the business has ever received lives inside that account.
- Keep the Webflow plan paid for 30 days after the DNS switch. That is the rollback.
